# Support

This file describes how to get help with RTIQA and how to engage with the community.

## Community support

Use GitHub as the primary support channel:

- GitHub Issues for bugs, feature requests, documentation questions, and project discussions.
- GitHub Discussions for broader community topics, if enabled.

## Reporting problems

Use the issue templates in `.github/ISSUE_TEMPLATE/` to submit:

- bug reports
- feature requests
- documentation issues

Include:

- a clear description of the problem
- reproduction steps
- environment details
- expected versus actual behavior

## Private support

RTIQA does not currently provide a dedicated support email address.
If you need confidential assistance, use the repository’s private security contact or GitHub Security Advisories when available. Do not use public issues for confidential reports.

## Contribution support

If you are contributing to RTIQA and need help:

- read `CONTRIBUTING.md`
- open an issue with questions
- propose a feature or improvement via an issue

## Community expectations

Keep support requests respectful and focused.
Provide enough detail to help responders diagnose the issue quickly.

If the repository hosts a discussion category for RTIQA, use it for design and roadmap conversations rather than bug reports.
