# Security Policy

This document describes how RTIQA handles security issues and vulnerability reports. It applies to repository content, documentation, and infrastructure references.

## Supported versions

We support the active branch and any documented release branches. Security fixes are provided for the maintained branches described by the project.

## Reporting a vulnerability

If you discover a security issue, report it privately instead of opening a public issue.

Preferred reporting channels:

- GitHub Security Advisories, if enabled for this repository
- the repository’s private security contact path

If neither channel is available, contact maintainers through GitHub support with a private request.

Please include:

- a concise description of the issue
- affected versions or branches
- reproduction steps
- impact assessment
- any relevant proof-of-concept information

## Response process

After receiving a report, maintainers will:

1. Acknowledge receipt in a timely manner.
2. Confirm the report and assign a severity rating.
3. Coordinate a remediation and verify the fix.
4. Share disclosure and release details when appropriate.

## Security practices

RTIQA follows these practices:

- secure configuration and deployment guidance
- minimal privileged access
- encrypted storage of secrets where appropriate
- dependency updates and vulnerability patching
- security review during code and design reviews

## Disclosure policy

Public disclosure is coordinated with the reporter and follows responsible disclosure practices.
Do not publish exploit details or proof-of-concept code until the issue is fixed or approved for disclosure.

## Safe reporting

If you are unsure whether information should be public, use private reporting channels first.

If the repository does not expose a private channel, contact the repository maintainers through GitHub support or a private issue.
