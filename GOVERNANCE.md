# Governance Model

RTIQA is governed as an open-source community project with a focus on transparency, collaboration, and sustainable growth.

## Governance principles

- open participation
- merit-based leadership
- transparent decision-making
- inclusive collaboration
- clear accountability

## Project structure

### Maintainers

Maintainers are contributors with merge rights who are responsible for:

- reviewing and merging contributions
- managing releases
- enforcing project standards
- guiding technical direction
- resolving community questions and conflicts

### Contributors

Contributors may:

- open issues
- submit pull requests
- propose enhancements
- contribute documentation
- participate in discussions

### Reviewers

Reviewers provide feedback and help ensure contributions meet quality expectations.

## Decision-making

Decisions are guided by their scope and impact.

### Types of decisions

- **Operational**: repository maintenance, documentation, and process updates.
- **Technical**: architecture, platform integration, and implementation strategy.
- **Governance**: policies, community roles, and release criteria.

### Decision process

1. Propose the decision in a GitHub issue or discussion.
2. Document the rationale and alternatives.
3. Review with maintainers and the community.
4. Reach consensus or majority support.
5. Record the outcome in project documentation or an ADR.

## Release policy

- `main` is the stable release branch.
- `develop` is the integration branch for active development.
- Release branches may be created from `main` for milestone delivery.
- Each release should include a changelog entry and release notes.

## Community participation

Contributions are welcome from individuals and organizations worldwide.
To participate:

- read `CONTRIBUTING.md`
- use issue templates and PR templates
- propose improvements in a new issue

## Conflict resolution

If disagreements arise:

1. Discuss respectfully in the issue or PR.
2. Seek input from multiple maintainers.
3. Ask the maintainer team to make a final decision.

## Communication

Preferred channels:

- GitHub Issues
- GitHub Discussions (if enabled)
- pull request comments

## Code ownership

RTIQA uses a lightweight ownership model based on:

- issue and PR assignment
- reviewer responsibility
- optional `CODEOWNERS` configuration in the future

## Transparency

Major decisions, governance changes, and release plans should be recorded publicly, ideally in GitHub issues, pull requests, or dedicated documentation pages.
